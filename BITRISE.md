# Bitrise: unsigned iOS build

1. Add `openeeer/OpenFlux_ios` as a project in Bitrise.
2. Configure Bitrise to load `bitrise.yml` from the repository root (not an
   unrelated configuration generated by the project scanner).
3. Select a macOS stack with Xcode 26.
   A Linux stack cannot build this app. Prefer an Apple Silicon machine.
4. Start a build on branch `main`, workflow `ios-unsigned`.

No Apple signing certificate or provisioning profile is required for this
workflow. The resulting IPA is **unsigned**: it must be signed separately before
installation on an iPhone. This workflow does not publish to TestFlight.

The build downloads Go module dependencies and installs Go with Homebrew if it
is missing. `GOTOOLCHAIN=auto` allows Go to use the module's required toolchain.
The device archive must contain the native Go engine, not the simulator stub.

Build artifacts are uploaded with the final deployment step, including on failure:

- `build.log`: full build-script diagnostics.
- `xcodebuild-archive.log`: raw Xcode output, once archiving starts.
- `engine-symbols.log`: native engine checks, if archiving succeeds.
- `OpenFlux-unsigned.ipa` and `OpenFlux.xcarchive.zip`: successful builds only.

No automatic Git triggers are enabled here. Start builds manually, or configure
the desired triggers in Bitrise after the first successful build.

Reference: https://docs.bitrise.io/en/bitrise-ci/references/configuration-yaml-reference
